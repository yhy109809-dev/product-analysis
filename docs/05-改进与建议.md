# 第五阶段：改进与建议方案集

> 定位：第四阶段交的是"问题"，本阶段交的是"**改法**"。
> 每条改进提案必须回答四件事：**改成什么样、改哪里、代价多大、怎么证明改好了**。
> 只写"建议增加回收站"不算方案，那还是需求。

---

## 一、本阶段真正要交的三样东西

| 交付物 | 是什么 | 不是什麼 |
|---|---|---|
| **8 份改进提案**（MNT-01～08） | 每条含目标、方案设计、实施代价、验收标准 | 不是 8 条需求标题 |
| **5 条治理建议**（S-01～05） | 不绑定单个缺陷，面向部署、质量、文档、上游协作 | 不是凑数的"建议加强测试" |
| **1 个已实施改进** | 真改一处、能 diff、能回归（MNT-03） | 不是"我们打算改" |

提案统一六段结构：

```
1 问题与证据 → 2 改进目标（可度量）→ 3 方案设计（含分叉）
→ 4 实施代价（人日/影响面/风险）→ 5 验收与回归 → 6 优先级与排期
```

## 二、八条改进提案

### MNT-01 删除的笔记可恢复（回收站）

**目标**：删除后进入回收站，保留期可配置（默认 30 天）；恢复后正文、标签、附件、可见性完全一致。

**方案（取决于一个待确认事实）**

- 若删除是**软删**（表里已有 `row_status`，Archive 用它）：
  - 复用 `row_status`，增加 `TRASHED` 枚举值；
  - `ListMemos` 默认过滤 `TRASHED`；
  - 新增三个 RPC：`ListTrashed`、`RestoreMemo`、`PurgeMemo`；
  - 前端加"回收站"页 + 恢复/彻底删除按钮；
  - 后台定时任务清理超过保留期的记录。
  - 代价：约 2.5 人日（接口 1、前端 1、测试 0.5）。
- 若删除是**物理删**（`DELETE FROM memo`）：
  - memo 表加 `deleted_ts`，`DeleteMemo` 改为写时间戳；
  - 所有查询补 `deleted_ts IS NULL`（这是主要工作量，容易漏）；
  - 其余同软删方案。
  - 代价：再加 2 人日（表结构 + 全查询排查 + 回归）。

**风险**：① 回收站里的笔记，附件不能提前清理，要跟笔记生命周期绑定；② 已删除笔记的分享链接应返回 404 而不是 500。

**验收**：
1. 删除后列表不可见、回收站可见；
2. 恢复后正文/标签/附件/可见性与删除前逐项一致；
3. 超过保留期自动清理，日志可查；
4. 删除后原分享链接立即失效。

**优先级**：P1｜**前提**：程先确认走哪个分支。

### MNT-02 并发提交不产生重复笔记

**目标**：同一用户、同一次提交意图，并发或重放 10 次只落 1 行。

**方案**：
- 客户端为每次"保存"生成 `request_id`（UUID），随 `CreateMemo` 一起提交；`proto` 增加 `optional string request_id`；
- 服务端加唯一约束 `(creator_id, request_id)`（单独建幂等表也可）；
- 冲突时**返回已存在的那条**而不是报错，保证前端表现一致；
- 前端现有的 `disabled={isSaving}` 保留，作为第一道防线。

**关键判断**：不能按"内容去重"——用户确实可能想发两条一样的。必须按 `request_id`。

**代价**：约 1.5 人日。**风险**：唯一索引上线前要去重历史数据；旧客户端不传 `request_id` 时退化为原行为（兼容）。

**验收**：
1. 同 `request_id` 并发 10 次 → 数据库 1 行、接口 10 次都返回同一条；
2. 不同 `request_id`、内容相同 → 允许落 2 行（不误伤）；
3. 不传 `request_id` 时行为与现在完全一致。

**优先级**：P1｜**分工**：杨写现象与验收，周写接口设计。

### MNT-03 超长标签不撑破页面

**目标**：任意长度的中英文标签都不产生横向滚动（`scrollWidth == clientWidth`）。

**方案**：
- 标签元素加 `max-width: 12rem; overflow: hidden; text-overflow: ellipsis; white-space: nowrap;`；
- 父容器补 `min-width: 0`（flex 子项不收缩导致的溢出，这是常见根因）；
- 悬停用 `title` 或 tooltip 显示全文；
- 移动端断点单独调一次。

**代价**：约 0.5 人日（含回归）。**风险**：`max-width` 设成固定宽度会把短标签也拉宽，用上限值不用定宽。

**验收**：
1. 300 / 1000 字符英文标签，`scrollWidth == clientWidth`；
2. 中文长标签、普通标签不回归；
3. 折叠态可查看全文。

**优先级**：P2｜**这条要做成真实 PR**（改动最小、回归最快），作为"已实施改进"的样板。

### MNT-04 版本与交付物可追溯

**目标**：任何人拿到报告，都能复现到同一个版本。

**方案**：
- 出《环境与基线卡 B-01》：系统、部署方式、`v0.31.0`、镜像 digest、数据目录、端口、账号；
- `docker-compose.yml` 里用 digest 固定镜像（`image: neosmemo/memos@sha256:...`）而不是 `:stable`；
- 启动脚本打印版本与 digest，写进日志；
- 报告每章开头引用 `B-01`。

**代价**：0.5 人日。**风险**：固定 digest 后升级要手动改，脚本里加一条"检查新版本"提示即可。

**验收**：报告出现基线卡编号；`docker inspect` 结果与卡一致；换机器按卡能复现。

**优先级**：P2。

### MNT-05 收缩暴露面并支持 HTTPS

**目标**：默认只本机可访问；需要局域网时显式开启；对外只走 HTTPS。

**方案**：
- 容器端口默认绑 `127.0.0.1:5230`；
- 需要局域网时，用 Caddy / Nginx 反代监听 443 转发到 5230，容器本身不直接对外；
- Caddy 方案可自动申请证书；内网环境用自签证书 + 客户端信任；
- 同步收紧 Windows 上 `com.docker.backend.exe` 的入站规则（现在这条规则让 5230 对整个局域网开放）；
- 文档写明"暴露面 = 反代，容器不直接对外"。

**代价**：约 1 人日（含证书调试）。**风险**：自签证书在手机上要装根证书，教学环境可在文档里给出替代步骤。

**验收**：
1. 默认配置下，局域网其他设备访问 5230 不通；
2. 开启反代后，只有 443 可达且为 HTTPS；
3. HTTP 访问自动跳转 HTTPS。

**优先级**：P1｜**依据**：端口 0.0.0.0 绑定 + HTTP 明文（丁，B 级证据）。

### MNT-06 备份 / 重建 / 迁移可执行

**目标**：一条命令备份、一条命令恢复；容器删除重建后笔记与附件 100% 可读。

**方案**：
- `backup.ps1`：`docker exec memos sqlite3 /var/opt/memos/memos_prod.db ".backup /tmp/b.db"` → `docker cp` 取出 → 打包附件目录 → 附一份 `manifest.json`（版本、digest、笔记数、附件数、时间）；
- `restore.ps1`：反向，恢复后自动核对三个数；
- 迁移时抽样校验附件哈希（抽 5 个文件即可）。

**代价**：约 1.5 人日。**风险**：WAL 模式下直接 `cp` 数据库文件会不一致，必须用 `.backup`；容器运行中和停止后两种状态都要测一遍。

**验收**：
1. 删除容器与数据卷 → `restore.ps1` → 笔记数、附件数、抽样哈希三项一致；
2. 记录 RTO（本次实测的恢复耗时）写进文档。

**优先级**：P1｜**分工**：刘主写，丁提供容器与挂载信息。

### MNT-07 关键缺陷有测试与合并门禁

**现状（已核对，不是"没测"）**：官方确已配置后端四组测试与前端检查，源码中有删除、私密权限、
导出附件、草稿缓存、标签识别五类用例；近期 Actions 的失败记录（#5977）经查是审批过期，
不是测试失败。真正的缺口是界面层两条完整操作没有用例（断网保存后刷新、双击只发一次请求）、
写入幂等没有服务端用例、覆盖率未取。

**目标**：补齐上述三条用例；未通过检查的 PR 无法合并。

**方案**：
- 前端补 2 条：断网→保存→恢复→刷新，草稿仍在；双击保存只发一次请求；
- 服务端补 1 条：同 `request_id` 并发只落一行；
- 仓库开 branch protection，把 CI 设为 required check；
- 覆盖率门槛先设"不下降"，稳定后再提绝对值；
- 失败判定要能区分"审批过期/环境原因"与"测试失败"。

**代价**：约 1 人日。**风险**：门槛设太高会卡住正常提交，先做"不下降"。

**验收**：三条用例在 CI 中跑通；未通过的 PR 无法合并；覆盖率不下降。

**优先级**：P2｜**分工**：苏主写。

---

### MNT-08 分享链接可查、可撤、可审计

**目标**：能看到自己发过哪些分享链接；撤销立即生效；有访问记录。

**方案**：
- 分享列表展示：创建时间、最后访问时间、访问次数、状态；
- 支持单条撤销与批量撤销；
- 撤销后鉴权层立即拒绝（不依赖缓存过期）；
- 对 share token 单独限流，防遍历。

**代价**：约 1 人日。**风险**：访问计数会带来写放大，用异步或采样写。

**验收**：撤销后 1 秒内原链接失效；列表状态与实际一致；计数与日志对得上。

**优先级**：P2。

## 三、五条治理建议（不绑定单条缺陷）

| 编号 | 建议 | 为什么值得写 |
|---|---|---|
| S-01 | 部署形态固化为 Compose + 反代 + 定时备份，替代现在的手工 `docker run` | 现在的部署靠人和脚本记忆，换台机器就复现不了 |
| S-02 | 质量门禁：分支保护 + 覆盖率不下降 + 发布前 upgrade smoke 必跑 | 对应第四阶段 Q6：配置存在≠有效 |
| S-03 | 给上游补一份《自部署运维 checklist》，作为文档 PR 贡献 | 低成本、高可见度的社区贡献 |
| S-04 | 把 MNT-02（幂等）和 MNT-03（标签溢出）做成 PR 提给 usememos | 从"提需求"升级为"参与维护"，是本课程最贴题的动作 |
| S-05 | 安全基线：默认最小暴露 + 强制 HTTPS + 固定升级节奏 | 对应 MNT-05，把一次性配置变成制度 |

## 四、已实施的改进（样板）

MNT-03 做成一个真实 PR，报告里用"改前 / 改后 / 回归"三张图说明：

1. **改前**：300 字符英文标签，`scrollWidth 2955 px` / 视口 `1422 px`，底部出现横向滚动条；
2. **改动**：标签组件加 `max-width` 与省略号，父容器补 `min-width: 0`（约 3 行样式）；

这一节是整份报告里唯一"我们真的改了代码"的证据，务必保留。
