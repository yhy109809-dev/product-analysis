# MNT-06 备份 / 重建 / 迁移可执行

| 项 | 内容 |
|---|---|
| 类型 | 可靠性 |
| 证据 | EV-07（A/B 级） |
| 优先级 | P1 |
| 关联 | C-10 |
| Issue | #6 |


## 1 现象

网页导出 / 导入已验证可用（ZIP 含附件与记录映射），但容器删除重建、断电中断、
跨环境迁移三种场景均未验证；现有备份依赖人工复制数据目录。

## 2 影响

数据目录中数据库与附件分离存放，只复制数据库会漏附件；WAL 模式下直接复制数据库文件
还可能出现不一致。发生磁盘故障或换机时，恢复结果不可预期。

## 3 期望

一条命令完成备份、一条命令完成恢复；容器删除重建后，笔记与附件 100% 可读。

## 4 方案

- `scripts/backup.ps1`：`docker exec memos sqlite3 ... ".backup /tmp/memos.db"` → `docker cp` 取出
  → 打包附件目录 → 生成 `manifest.json`（版本、digest、笔记数、附件数、时间）；
- `scripts/restore.ps1`：反向恢复，并自动核对笔记数、附件数、抽样哈希；
- 迁移时抽样校验 5 个附件文件哈希；
- 记录 RTO（实测恢复耗时）。

## 5 代价与风险

约 1.5 人日。风险：WAL 模式不能直接复制数据库文件，必须用 `.backup`；
容器运行中与停止后两种状态都要测一遍。

## 6 验收

- [ ] 删除容器与数据卷 → `restore.ps1` → 笔记数、附件数、抽样哈希三项一致；
- [ ] 备份包含 `manifest.json`，字段完整；
- [ ] RTO 实测值写入文档。
