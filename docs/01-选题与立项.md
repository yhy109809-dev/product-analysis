# 01 选题与立项

## 1.1 为什么选 Memos

- **真实在用的开源项目**：仓库有完整的 Issue、CI、发布流程，适合做结构与维护分析，而不是只读代码。
- **自部署形态**：安装本身就是一个可复现的工程问题，能留下部署记录与踩坑证据。
- **技术栈覆盖前后端**：Go（`server/`、`store/`）+ React / TypeScript（`web/`）+ protobuf（`proto/`），一层一层能追下去。
- **体量适中**：7 个人在一个阶段内能摸清主干，不至于停在"画个框图"。

## 1.2 对象与版本

| 项 | 值 |
|---|---|
| 上游仓库 | https://github.com/usememos/memos |
| 研究版本 | v0.31.0 |

## 1.3 六阶段计划

| 阶段 | 目标 | 产出 |

## 1.5 协作方式

- **仓库**：本仓库，按章节分文件，保留每次修改记录；
- **问题与申请**：GitHub Issues，模板见 `.github/ISSUE_TEMPLATE/mnt.md`；
- **代码改动**：分支 + Pull Request + 至少 1 人 review；
- **证据**：`evidence/`，文件名为 `EV-编号-描述.png`，正文只引编号。
