# 02 安装部署

## 2.1 环境

| 项 | 值 |
|---|---|
| 操作系统 | Windows 11 家庭版中文版 |
| 容器 | Docker Desktop（WSL2 后端），容器名 `memos` |
| 镜像 | `neosmemo/memos:stable`（实际运行 Memos v0.31.0） |
| 端口 | `0.0.0.0:5230->5230/tcp` |
| 数据目录 | `C:\Users\DingSuYa\.memos`（挂载到容器 `/var/opt/memos`） |
| 数据库 | SQLite，`memos_prod.db` + WAL |

> 完整基线见 [基线卡 B-01](基线卡.md)。

## 2.2 部署步骤

1. 安装 Docker Desktop，启用 WSL2；
2. 拉取镜像（直连 Docker Hub 不稳定时使用镜像加速前缀，再重新打标签）；
3. 启动容器并映射 5230 端口、挂载数据目录；
4. 浏览器访问 `http://localhost:5230`，完成初始化与账号创建；
5. 执行 `scripts/环境自检.ps1`，8 项全部正常即视为部署成功。

## 2.3 踩坑记录

| 现象 | 原因 | 处理 |
|---|---|---|
| Docker 安装程序报磁盘不足 | 默认装到 C 盘 | 清理系统盘，规划 D 盘数据路径 |
| Docker Desktop 启动失败，提示 WSL 未安装 | 未启用 WSL2 | `wsl --install` 后重启 |
| Docker 启动卡住，日志提示代理配置 | 系统代理 + NAT 模式冲突 | 启动前临时关闭系统代理，或用 `启动Memos.ps1` |
| `docker pull` 超时 | 直连 Docker Hub | 使用镜像加速前缀拉取后重新 tag |
| `docker ps` 里端口没有 `0.0.0.0:5230->` | 端口发布失败（mirrored 模式） | 改回 NAT，`wsl --shutdown` 后重启 Docker |

## 2.4 端口与数据持久化

- 端口绑定 `0.0.0.0` 意味着局域网内其他设备可访问；可达性由 Docker Desktop 自动创建的
  `com.docker.backend.exe` 程序级入站规则控制（禁用该规则后立即不可达）。
- 数据落在宿主机目录，容器重建后数据保留；但**主机级备份与灾备**未在第四阶段验证，
  相关申请见 [MNT-06](../mnt/MNT-06.md)。

## 2.5 启动与自检

| 脚本 | 作用 |
|---|---|
| `scripts/启动Memos.ps1` | 临时关代理 → 启动 Docker → 等引擎就绪 → 恢复代理 → 启动容器 → 验证 200 |
| `scripts/环境自检.ps1` | 输出 8 项：引擎、容器、端口、本机访问、WLAN 地址、防火墙规则、系统代理、WSL 模式 |
| `scripts/backup.ps1` | 一致性备份数据库 + 附件 + 清单 |
| `scripts/restore.ps1` | 恢复并核对笔记数、附件数、抽样哈希 |
