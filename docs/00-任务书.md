操作手册（丁）全程**网页端可完成**，不用装 Git。### 1. 建仓库- 右上角 `+` → New repository- 名称：`memos-se-group`；可见性按课程要求（默认 Public，私有则把老师加为 collaborator）- 勾选 `Add a README file`- Create### 2. 拉人`Settings` → `Collaborators` → `Add people` → 输入 6 人的 GitHub 用户名 → 权限选 `Write`。### 3. 建目录仓库页 `Add file` → `Create new file`，文件名写 `docs/README.md`（斜杠会自动建目录），提交。同样办法建：```docs/        报告与任务书mnt/         维护申请单evidence/    证据截图（EV 编号）scripts/     备份恢复、环境自检.github/ISSUE_TEMPLATE/```### 4. Issue 模板新建 `.github/ISSUE_TEMPLATE/mnt.md`，内容：```markdown---name: 维护申请about: 甲方视角的维护申请条目title: "[MNT-xx] "labels: MNT---## 现象（可复现的操作与结果，一句话）## 影响（谁、什么场景、损失什么）## 期望（要什么行为，不写怎么改）## 验收标准- [ ] - [ ] ## 优先级P0 数据丢失或越权 / P1 功能不可用或高风险 / P2 体验缺陷 / P3 建议## 关联线索：　证据：EV-xx　关联结论：C-xx```### 5. 标签`Issues` → `Labels` → New label，建 10 个够用：`MNT`、`P0`、`P1`、`P2`、`待补证`、`已确认`、`已修复`、`方向-架构`、`方向-运维`、`方向-质量`### 6. 里程碑`Issues` → `Milestones` → New：`stage5-改进与建议`，Due date 11-08。### 7. 开 8 个 Issue`Issues` → `New issue` → 选「维护申请」模板 → 标题 `[MNT-03] 超长英文标签撑破页面` → 填六字段 → 右侧选 Labels（MNT + 优先级 + 状态）和 Milestone → Submit。八条标题：```[MNT-01] 删除的笔记无法恢复[MNT-02] 并发提交产生重复笔记[MNT-03] 超长英文标签撑破页面[MNT-04] 交付物无法追溯到确切版本[MNT-05] 端口对局域网开放且无 HTTPS[MNT-06] 缺少可执行的备份与重建流程[MNT-07] 关键缺陷无自动化测试与门禁[MNT-08] 分享链接缺少审计与批量撤销```### 8. 走一个 PR（MNT-03）1. 打开 `web/src` 里那个标签组件文件 → 右上铅笔 `Edit`；2. 加样式（例：`max-width: 12rem; overflow: hidden; text-overflow: ellipsis; white-space: nowrap;`）；3. 页面下方 `Commit changes` → 选 `Create a new branch for this commit and start a pull request` → 分支名 `fix/mnt-03-tag-overflow` → Propose changes；4. PR 标题 `[MNT-03] 限制标签最大宽度`，描述写 `Closes #3` + 改前改后截图 + 回归方式；5. 右侧 `Reviewers` 选周 → 周点 `Review changes` → `Approve` → `Merge pull request`。### 9. 纪律- 每人一个分支 `mnt-0x-姓名`，不许直接推 `main`；- 一条 MNT 对一个 Issue，一个 PR 只改一件事；- 提交前脱敏：内网 IP、Token、账号口令一律换成 `<HOST>` `<TOKEN>` `<ACCOUNT>`。---## 五、最终报告目录**总页数目标 28–34 页**，六章 + 附录。每章都已有现成素材，不需要重新调研。| 章 | 标题 | 主要素材 | 主笔 | 页数 ||---|---|---|---|---|| — |
