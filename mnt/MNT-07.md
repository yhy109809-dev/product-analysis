# MNT-07 关键缺陷有测试与合并门禁

| 项 | 内容 |
|---|---|
| 类型 | 可维护性 |
| 证据 | EV-08（待补） |
| 优先级 | P2 |
| 关联 | 线索 10—12 |
| Issue | #8 |


## 1 现象

上游配置了后端测试、前端检查、协议检查与发布前冒烟，但本组尚未核对对应版本的 Actions
运行结果（通过项、跳过项、覆盖率），也未确认这些检查是否为强制合并条件。

## 2 影响

"配置存在不等于有效"。若关键路径（删除、权限、并发）没有测试覆盖，同类问题会反复出现，
且改动无法自动回归。

## 3 期望

三类关键问题各有一条自动化用例；未通过检查的 PR 无法合并。

## 4 方案

- store 层补 2 条：软删后列表过滤、同 `request_id` 幂等冲突；
- 前端补 1 条：长标签渲染后 `scrollWidth == clientWidth`；
- 仓库开启 branch protection，把 CI 设为 required check；
- 覆盖率门槛先设"不下降"，稳定后再提绝对值。

## 5 代价与风险

约 1 人日。风险：门槛设太高会卡住正常提交，先做"不下降"。

## 6 验收

- [ ] 三条用例在 CI 中跑通；
- [ ] 未通过检查的 PR 无法合并；
- [ ] 覆盖率不低于改动前。
