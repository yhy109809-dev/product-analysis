# MNT-05 收缩暴露面并支持 HTTPS

| 项 | 内容 |
|---|---|
| 类型 | 安全 |
| 证据 | EV-06（B 级） |
| 优先级 | P1 |
| 关联 | C-08 |
| Issue | #5 |


## 1 现象

容器端口绑定 `0.0.0.0:5230`，Docker Desktop 自动创建的程序级入站规则使 5230 对整个局域网开放；
应用使用 HTTP 明文传输，无传输层保护。测试中其他设备可直接打开登录页。

## 2 影响

同一网络内的任何设备都能访问服务，只能依赖应用层登录鉴权；凭据与笔记正文在传输中为明文，
在公共 Wi-Fi 或校园网环境下存在被监听的风险。

## 3 期望

默认仅本机可访问；确需局域网访问时显式开启；对外只走 HTTPS。

## 4 方案

- 容器端口默认绑 `127.0.0.1:5230`；
- 需局域网访问时，用 Caddy / Nginx 反代监听 443 转发到 5230，容器本身不直接对外；
- Caddy 可自动申请证书；内网环境用自签证书 + 客户端信任；
- 同步收紧 `com.docker.backend.exe` 的入站规则；
- 文档写明"暴露面 = 反代，容器不直接对外"。

## 5 代价与风险

约 1 人日（含证书调试）。风险：自签证书在手机上需安装根证书，文档里给出替代步骤。

## 6 验收

- [ ] 默认配置下，局域网其他设备访问 5230 不通；
- [ ] 开启反代后，仅 443 可达且为 HTTPS；
- [ ] HTTP 访问自动跳转 HTTPS。
