# MNT-01 删除的笔记可恢复（回收站）

| 项 | 内容 |
|---|---|
| 类型 | 功能缺失 |
| 证据 | EV-10（C 级，待补代码证据） |
| 优先级 | P1 |
| 关联 | C-01、C-09 |
| Issue | #1 |


## 1 现象

删除一条笔记后，笔记从时间线消失，设置页与笔记操作菜单中均无回收站、撤销或恢复入口；
误删后只能通过手工恢复数据库备份找回。

## 2 影响

用户一次误操作即造成内容永久丢失。对从其他笔记软件迁移来的用户，习惯性使用"删除"而非"归档"，
误删概率更高。现有替代方案 Archive 只能隐藏内容，且归档会长期占用存储，需要人工清理。

## 3 期望

删除的笔记进入回收站，保留期可配置（默认 30 天）；期间可一键恢复，恢复后正文、标签、
附件与可见性完全一致；超过保留期自动清理。

## 4 方案

取决于删除实现方式，需先确认走哪个分支：

**分支 A——若已是软删**（表中已有 `row_status`，Archive 复用它）

- 复用 `row_status`，增加 `TRASHED` 枚举值；
- `ListMemos` 默认过滤 `TRASHED`；
- 新增三个 RPC：`ListTrashed`、`RestoreMemo`、`PurgeMemo`；
- 前端增加"回收站"页与恢复 / 彻底删除按钮；
- 后台定时任务清理超期记录。

**分支 B——若是物理删**（`DELETE FROM memo`）

- memo 表增加 `deleted_ts`，`DeleteMemo` 改为写时间戳；
- 所有查询补 `deleted_ts IS NULL`（主要工作量，容易漏）；
- 其余同分支 A。

## 5 代价与风险

| 项 | 分支 A | 分支 B |
|---|---|---|
| 工作量 | 约 2.5 人日 | 约 4.5 人日 |
| 影响面 | 接口 + 前端 | 表结构 + 全部查询 |

风险：① 回收站内笔记的附件不能提前清理，需与笔记生命周期绑定；② 已删除笔记的分享链接应返回 404，而不是 500。

## 6 验收

- [ ] 删除后列表不可见、回收站可见；
- [ ] 恢复后正文 / 标签 / 附件 / 可见性与删除前逐项一致；
- [ ] 超过保留期自动清理，日志可查；
- [ ] 删除后原分享链接立即失效。
